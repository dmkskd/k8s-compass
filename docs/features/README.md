## Architecture Overview

All tabs share:
- **State Management**: Zustand store (`explorerStore.ts`)
- **Data Layer**: DuckDB WASM querying Parquet files
- **Search**: Global `searchQuery` in store, filtered client-side per view

## Data Flow

```
Parquet Files (source of truth)
       ↓
DuckDB WASM (browser)
       ↓
React Hooks (useDB, useQuery, executeQuery)
       ↓
Zustand Store (explorerStore)
       ↓
View Components
```

## Search Architecture

The global search (`searchQuery` in store) is:
1. Set via Header component's search input
2. Consumed by each view component
3. Filtered **client-side in memory** after data is loaded from DuckDB

This means:
- Data is first loaded from DuckDB into React state
- Search filtering happens in JavaScript `useMemo` hooks
- No SQL `WHERE` clauses are used for search (except Analytics)

### Search by Tab

| Tab | Search Scope | Implementation |
|-----|--------------|----------------|
| API Explorer | All Kinds in selected version | Client-side filter on `nodes[]` |
| Releases | Features in selected release only | Client-side filter on `release.features[]` |
| Control Plane | Component flags, kubectl commands, feature gates | Local search within modal |
| Learn | All content | Client-side filter on `content[]` |
| Analytics | N/A (use SQL WHERE) | Direct DuckDB query |

### Why Client-Side Filtering?

1. **Simplicity**: No need to rebuild queries on every keystroke
2. **Performance**: Data is already in memory, filtering is fast
3. **Responsiveness**: Instant feedback without network/DB round-trips

### Current Limitations

**Releases search is scoped to the selected release only.** The global search in the Releases tab filters features/changes within the currently selected release. Cross-release search would require:
1. Loading all releases into memory (expensive, ~10+ releases)
2. Or running a DuckDB query across all releases (not implemented)

**Workaround:** Use Analytics tab for cross-release queries:
```sql
SELECT f.version, k.kep, k.title
FROM 'features.parquet' f
JOIN 'keps.parquet' k ON f.kep = k.kep
WHERE k.title ILIKE '%sidecar%'
```

## Common Patterns

### Loading Data
```typescript
// Hook-based (most tabs)
const { data, loading, error } = useQuery<T>(sql)

// Imperative (for complex multi-query loads)
const results = await executeQuery<T>(sql)
```

### Filtering with Search
```typescript
const filtered = useMemo(() => {
  if (!searchQuery.trim()) return data
  const q = searchQuery.toLowerCase()
  return data.filter(item => 
    item.name.toLowerCase().includes(q)
  )
}, [data, searchQuery])
```

### Table References
```typescript
// Use parquet() helper for table names
const sql = `SELECT * FROM ${parquet('kinds')} WHERE version = '1.35'`
// Expands to: SELECT * FROM 'kinds.parquet' WHERE version = '1.35'
```
