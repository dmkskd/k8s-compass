# Releases

The Releases tab shows Kubernetes release history with features, changes, and patch releases.

## Overview

**Main Component:** `ReleasesView.tsx`

**Layout:**
1. Timeline bar (top) - clickable release nodes
2. Release details panel - expandable accordion sections

## Data Loading

```
useReleaseIndex()
  → DuckDB query on releases.parquet
  → Returns: { releases[], latestVersion }

useReleaseNotes(version)
  → Multiple parallel DuckDB queries:
     - releases (metadata)
     - features (joined with keps)
     - deprecations
     - release_changes
     - action_required
     - security_cves
     - patch_releases
     - patch_release_changes
     - patch_security_fixes
  → Returns: full ReleaseNotes object
```

**Key Point:** Data is loaded **per-release** on demand when a release is selected.

## Search Behavior

### Global Search (Header)

The global `searchQuery` from the store filters **only the currently selected release's features**:

```typescript
const filteredFeatures = useMemo(() => {
  // ... other filters ...
  
  // Apply global search if present
  if (searchQuery.trim()) {
    const q = searchQuery.toLowerCase()
    features = features.filter(f => 
      f.title.toLowerCase().includes(q) || 
      f.kep.toLowerCase().includes(q) ||
      f.sig.toLowerCase().includes(q) || 
      f.description?.toLowerCase().includes(q)
    )
  }
  return features
}, [release, featureFilter, featureLabelFilter, featureSearch, searchQuery])
```

### Section-Specific Search

Each accordion section has its **own local search state**:

```typescript
const [featureSearch, setFeatureSearch] = useState('')
const [changeSearch, setChangeSearch] = useState('')
const [noticeSearch, setNoticeSearch] = useState('')
const [patchSearch, setPatchSearch] = useState('')
```

These are independent of the global search and filter within their respective sections.

### Current Limitation: Single-Release Scope

**The search only works within the selected release.** This is because:

1. Only one release's data is loaded at a time (`useReleaseNotes(activeRelease)`)
2. Cross-release search would require either:
   - Loading all releases into memory (expensive, ~10+ releases × large data)
   - Running a DuckDB query across all releases (not implemented)

**Workaround for cross-release search:** Use the Analytics tab with SQL:
```sql
SELECT version, kep, title 
FROM features 
JOIN keps ON features.kep = keps.kep
WHERE keps.title ILIKE '%sidecar%'
```

## Sections

### Content
- External links (blogs, docs, videos) related to the release
- Data from `content_links.parquet` filtered by `target_type='release'`

### Features
- KEP enhancements graduating in this release
- Filterable by stage (stable/beta/alpha) and labels
- Has autocomplete label search

### Notices
- Sub-sections: Urgent, Security, Deprecations
- Urgent upgrade notes from CHANGELOG
- CVEs with affected/fixed versions
- Deprecation notices with replacement suggestions

### Changes
- Raw PR changes grouped by kind (feature, bugOrRegression, apiChange, etc.)
- Includes enrichment data if available (problem, fix, impact)

### Patch Releases
- List of patch versions (e.g., 1.35.1, 1.35.2)
- Each with its own changes and security fixes

## State Management

```typescript
// explorerStore.ts
{
  activeSection: 'releases',
  selectedRelease: '1.35',  // Currently viewed release
  selectedVersion: '1.35',  // Also used for API Explorer
  searchQuery: '',          // Global search
}

// Local state in ReleasesView
{
  expandedSection: 'features' | 'notices' | 'changes' | 'patches' | null,
  featureFilter: 'stable' | 'beta' | 'alpha',
  featureLabelFilter: string | null,
  changeFilter: string | null,
  // Section-specific searches
  featureSearch, changeSearch, noticeSearch, patchSearch
}
```

## Data Tables Used

| Table | Purpose | Generated By |
|-------|---------|--------------|
| `releases` | Release metadata (version, codename, date, counts) | `build-release` |
| `keps` | KEP master data (title, sig, description, labels) | `build-release` |
| `features` | KEP graduations per release (version, kep, stage) | `build-release` |
| `deprecations` | Deprecation notices | `build-release` |
| `release_changes` | PR changes by kind | `build-release` |
| `action_required` | Action required notes | `build-release` |
| `security_cves` | CVE information | `build-release` |
| `patch_releases` | Patch release metadata | `build-release` |
| `patch_release_changes` | Changes in patch releases | `build-release` |
| `patch_security_fixes` | Security fixes in patches | `build-release` |
| `content_links` | External content (filtered by release) | `add-content`, `fetch-sched` |

## TODO / Known Issues

1. **Cross-release search**: Not supported - search only works within selected release
2. **Performance**: Loading full release data can be slow for releases with many changes
3. **Enrichment coverage**: Not all releases have LLM-enriched descriptions
4. **Timeline UX**: Year markers positioning could be improved
5. **Mobile**: Accordion sections not optimized for small screens
