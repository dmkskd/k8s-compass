# API Explorer

The API Explorer tab provides visual exploration of the Kubernetes API schema.

## Views

### Constellation View (`ConstellationView.tsx`)

A 3D force-directed graph showing all Kubernetes Kinds as nodes with relationship edges.

**Data Loading:**
```
useConstellationDataDB(version)
  → executeQuery() to DuckDB
  → Loads: versions, api_groups, kinds, kinds_relationships
  → Returns: nodes[], edges[], groups[]
```

**Search Behavior:**
- Global `searchQuery` from store
- Filtered **client-side in memory** via `useMemo`:
```typescript
const visibleNodes = useMemo(() => {
  if (searchQuery && searchQuery.trim()) {
    const query = searchQuery.toLowerCase().trim()
    result = result.filter((n) => 
      n.kind.toLowerCase().includes(query) ||
      n.group.toLowerCase().includes(query) ||
      n.shortNames?.some(sn => sn.toLowerCase().includes(query))
    )
  }
  return result
}, [nodes, selectedGroup, searchQuery])
```

**Features:**
- Drag to spin the constellation
- Scroll to zoom
- Click node to open SpecStructure overlay
- Nodes sized by field count
- Shapes indicate scope (sphere=namespaced, octahedron=cluster)
- Edge lines show relationships (owns, selects, references)

**Known Issues:**
- Performance degrades with many visible nodes
- Edge rendering can be slow on large datasets

### Sunburst View (`SunburstView.tsx`)

A D3-based sunburst diagram showing API hierarchy: Groups → Versions → Kinds.

**Data Loading:**
- Same as Constellation: `useAPITreeDB(version)`
- Builds hierarchy via `buildHierarchy(groups)`

**Search Behavior:**
- Global `searchQuery` from store
- Filtered **client-side** via `useMemo`:
```typescript
const matchingKinds = useMemo(() => {
  if (!searchQuery || !searchQuery.trim()) return null
  const query = searchQuery.toLowerCase().trim()
  const matches = new Set<string>()
  
  groups.forEach(group => {
    group.versions.forEach(version => {
      version.kinds.forEach(kind => {
        if (
          kind.name.toLowerCase().includes(query) ||
          group.name.toLowerCase().includes(query) ||
          kind.shortNames?.some(sn => sn.toLowerCase().includes(query))
        ) {
          matches.add(kind.name)
        }
      })
    })
  })
  return matches
}, [searchQuery, groups])
```
- Non-matching nodes are dimmed (opacity 0.15)

**Features:**
- Click group to zoom in
- Click center to zoom out
- Drag to spin
- Scroll to zoom
- Click kind to open SpecStructure

### SpecStructure (`SpecStructure.tsx`)

Overlay panel showing full schema for a selected Kind.

**Data Loading:**
- Schema loaded via `loadSchemasForVersion(version)` → fetches from `kinds.parquet` `schema_json` column
- KEP links loaded via `useKindKepLinks(version, kind, group)`

**Search Behavior:**
- Has its **own local search** (`useState`) separate from global
- Searches field names, paths, and descriptions
- Highlights matches and auto-expands matching paths

**Features:**
- Tree view (hierarchical) and flat view modes
- Filter by version added (new fields)
- Filter by KEP-linked fields
- Click field to see details (type, description, KEP link)
- Links to kubernetes.io docs

## Data Tables Used

| Table | Purpose | Generated By |
|-------|---------|--------------|
| `releases` | K8s releases with version info (is_latest) | `build-release`, `fetch` |
| `api_groups` | API groups per version | `fetch` |
| `kinds` | All Kinds with metadata + `schema_json` | `fetch` |
| `kinds_relationships` | Kind-to-Kind relationships | `fetch` |
| `field_kep_links` | Field-to-KEP mappings | `link-keps` |
| `keps` | KEP master data (for SpecStructure KEP links) | `build-release` |

## TODO / Known Issues

1. **Performance**: Large schemas (e.g., Pod) can be slow to render in SpecStructure
2. **Search scope**: Global search only filters visible nodes, doesn't search field names
3. **Relationship edges**: Some edges may be missing due to inference limitations
4. **Mobile**: 3D views not optimized for touch/mobile
